# Launcher lane report (lane/launcher)

A patched **moonlight-qt 6.1.0** (submodule `third_party/moonlight-qt`, tag v6.1.0 f786e94c, never edited in place)
whose stream start hands off to the native OpenXR client. Everything else in the flat UI is stock.

## Patches (what and why)
1. `0001` `app/app.pro`: build `mlxrhandoff.cpp/.h`.
2. `0002` `app/main.cpp`: own QSettings/cache profile "Moonlight XR Native" (org = app; `MLXR_LAUNCHER_PROFILE=Moonlight` selects Moonlight Qt's names); first-run import of the flatpak config; window title/display name "Moonlight XR Native", desktop file name `moonlight-xr-launcher` (was `com.moonlight_stream.Moonlight`, so the two apps do not share an app id); `MLXR_LAUNCHER_SELFTEST` hook.
3. `0003` `Session::exec()` calls new `Session::execVr()` when the hand-off is enabled (client found, `MLXR_HANDOFF` not 0); everything else in `Session` is untouched, so with no client installed (or `MLXR_HANDOFF=0`) the launcher streams flat exactly like stock. New signal `vrStreamStarted()`. `StreamSegue.qml`: connects it and sets the stock tip (below); after the stream, restarts polling if it idled out (the window is never hidden, so the app list refreshes). 
4. `0004` test hooks: `objectName: "stackView"` in main.qml and one call in main.cpp (env-driven, inert).

## Hand-off contract
Pairing: before each launch `exportPairing()` writes, into `$MLXR_CONFIG_DIR` (default `~/.config/moonlight-xr`, the native client's dir): `client.pem`/`client.key`/`uniqueid` (the launcher's identity; if a different identity was there it is kept as `*.bak-<stamp>`), `servercerts/<uuid>.pem` (the pinned server cert from the live computer object) and the `hosts.ini` record (name, the address that answers now first, then manual/local/remote/IPv6 as extra addresses, MAC, ports; other hosts in the file are kept). This runs in-process from the computer Moonlight just talked to, so it is exact and needs no Python or timing against QSettings writes.

argv: `<client> --host <uuid> --app <id> --mode WxHxFPS [--bitrate KBPS] [--h264] [--sw-decode] [--audio 51|71] [--packet-size N] --exit-to-caller` (+ `MLXR_LAUNCHER_EXTRA_ARGS`). Mapping: width/height/fps/bitrate as set in Moonlight's Settings; "Force H.264" -> `--h264` (auto, HEVC and AV1 leave the client's own HEVC/H.264 choice; AV1, HDR, YUV 4:4:4 are not supported by the client); "Force software decoding" -> `--sw-decode`; audio 5.1/7.1 -> `--audio`; packet size -> `--packet-size` (also "treat as local", as Moonlight does). Not mapped (flat-window only or unsupported): window mode, V-Sync, frame pacing, HDR, 4:4:4, game optimizations (SOPS), play audio on host, multi-controller, quit-app-after (the client always ends the host session on the bar's Exit), mouse/gamepad options (VR cog and the pad lane own those).

env of the child: inherited minus `LD_LIBRARY_PATH`, `MESA_GL(SL)_VERSION_OVERRIDE`, `QSG_RENDER_LOOP`, `QML_DISK_CACHE_PATH`, `SDL_VIDEODRIVER`, `SDL_VIDEO_*_WMCLASS`; cwd = the client's directory (assets are found relative to it); `PR_SET_PDEATHSIG=SIGTERM` so it never outlives the launcher; output (stdout+stderr) is written to `moonlight-console.log` (`$MLXR_LOG_DIR`, default `~/Games/MoonlightXRNative`).

Exit codes (`app/main.c`, with `--exit-to-caller` the message is one stderr line `MLXR_ERROR: <text>`, shown in Moonlight's own error dialog):
0 normal (the bar's Exit: host session ended; SteamVR quit; `--seconds`), 1 VR session could not start / unclassified, 2 usage, 3 host unreachable, 4 no such paired host, 5 no such app, 6 host refused the launch or the stream would not connect, 10 stream ended by itself (host closed it or network lost; dialog shown), **11 left with the disconnect chord: not an error, no dialog, the host's session keeps running**. A crash by signal gives "The VR client crashed. See moonlight-console.log"; a code without a message gives "The VR client stopped with code N".
After exit 11 (or 0) the launcher does nothing special: the window was never hidden, polling continues/restarts, and the app grid shows the running app with Resume / Quit through Moonlight's own polling, exactly as stock after a disconnect (stock returns to the same view). Quitting the launcher during a stream sends the client SIGTERM, which ends the stream like SteamVR quitting does.
CLI: `moonlight-xr-launcher stream <host> <app>` is stock's (CliStartStreamSegue -> Session -> hand-off, `quitAfter` quits the launcher afterwards); `pair`, `list`, `quit` untouched. Debug: `MLXR_LAUNCHER_DRYRUN=1` prints `MLXR_LAUNCHER_DRYRUN: <exact command line>` (also appended to `$MLXR_LAUNCHER_DRYRUN_OUT`) instead of running it (`=fail:CODE:message` plays a failing client); `MLXR_LAUNCHER_HIDE_WINDOW=1` hides the Qt window during the stream like stock's SDL flow; `MLXR_NATIVE_CLIENT` overrides the client path.

## Config and pairing sharing
Own profile `~/.config/Moonlight XR Native/Moonlight XR Native.conf` (cache `~/.cache/Moonlight XR Native/`). On the first run only (file absent), if the flatpak's `~/.var/app/com.moonlight_stream.Moonlight/config/Moonlight Game Streaming Project/Moonlight.conf` exists (else the native `~/.config/Moonlight Game Streaming Project/Moonlight.conf`; `MLXR_SEED_CONF` overrides, `MLXR_NO_SEED=1` disables) it is **copied whole** (client certificate + key + unique id, every PC with addresses, MAC, pinned server certificate and app list, all settings), read-only on the source; then these keys are rewritten for the headset: `width=2560 height=1440 fps=90 bitrate=80000 hdr=false yuv444=false videocfg=0 audiocfg=0 packetsize=0` and `mlxr/seeded_from=<path>` is added (the owner's flatpak has 1080p144 31 Mbps, chosen for a flat window). The user changes them in Settings as usual. Box-art cache is not copied (re-fetched from the hosts). Because the launcher keeps the same identity as the flatpak and as the earlier `seed-from-moonlight-qt.sh` import, the PC needs no re-pairing, and pairing done in the launcher works for the VR client at once.

## User-visible differences from stock moonlight-qt 6.1.0 (complete list)
1. Window title / app name: "Moonlight XR Native" instead of "Moonlight"; window class / desktop file name `moonlight-xr-launcher`; config and cache live under that name (above).
2. When a stream starts and the native client is installed, the stock StreamSegue stays up ("Starting <app>..." and spinner, stock text) and only the tip line changes to stock's wording with the new chord: **"Tip: Press Start+Select+L2+R2 to disconnect your session"** (strings: `qsTr("Tip:")`, `qsTr("Press %1 to disconnect your session")`, `qsTr("Start+Select+L2+R2")`; the stock L1/R1 and Ctrl+Alt+Shift+Q variants do not apply to the VR client). The window is not hidden (stock hides it when the SDL window opens); set `MLXR_LAUNCHER_HIDE_WINDOW=1` to hide it.
3. The hand-off's failures use the stock error dialog with the client's message (new texts: "The host is unreachable...", "The VR client stopped with code N...", "The stream ended: the host closed the session or the connection was lost", pairing export errors).
4. Streaming is done by the VR client: stock's SDL stream window, its decoder checks and `quitAppAfter` do not apply while the client is installed.
5. First-run settings override (above). Nothing else: no page, dialog, icon, string, shortcut or gamepad behaviour of the grid, pairing, Settings, Resume/Quit changed. Verified for the computer grid and Settings page by pixel comparison (below).

How Game Mode shows the flat window (Qt picks Wayland/X from the environment; if Game Mode shows it black or tiny, try `QT_QPA_PLATFORM=xcb` / `wayland` in the wrapper) and its controller/mouse use (stock behaviour); the switch into VR when a stream starts (SteamVR must come up from the client's OpenXR instance; the flat window stays visible meanwhile) and back after the bar's Exit or the chord; Resume after a chord disconnect; the Tip line; closing the launcher during a stream; first launch with the real flatpak config (PC list, no re-pairing, VR default settings).

## Install steps for lane P
`launcher/build.sh` (≈2 min with `-j3`), then `DEST=<app dir> launcher/install-launcher.sh` after `packaging/install.sh` (it puts `moonlight-xr-launcher` and `moonlight-xr-launcher.sh` next to `moonlight-xr`). The Steam shortcut (2761093165) would run `moonlight-xr-launcher.sh` instead of `moonlight-xr.sh` once the owner wants the flat UI first; this lane did not touch it. `tests/launcher/CMakeLists.txt` needs `add_subdirectory(tests/launcher)` at the top level (or run it standalone, see its header). The launcher needs the host's Qt6 (base, declarative, svg), SDL2, SDL2_ttf, FFmpeg, opus, OpenSSL, libva/libdrm: all SteamOS packages (ldd audit ok).
