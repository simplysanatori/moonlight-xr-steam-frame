# Translations of the headset UI

PLAN item 6.1. Only the in-headset panels (`ui/`) are covered here. The flat launcher is moonlight-qt
and has its own translations (its Language row); nothing here touches them.

## How a string reaches the headset

* Every word the panels draw is an id in `ui/ui_strings.h` (`UIS_*`), keyed by upstream's Android
  resource name, with its English text. The panels ask `ui_str(id)` at the moment they draw.
* The panels (`ui/panel_*.c`) are rasterised on the CPU at run time, through stb_truetype, from the
  bundled Noto Sans (`assets/fonts/`), into one RGBA atlas (`ui_atlas_rect`, `UI_ATLAS_W` x
  `UI_ATLAS_H`) that `xr/xr_assets.c` uploads to a single swapchain. The glyphs go through an 8-bit
  glyph cache (1024 x 1024, flushed when full) that holds only what is on screen.
* Nothing is pre-rendered at build time: there is no per-language atlas to build or ship. A second
  language costs its strings in the binary (about 2 KB of text and 1.5 KB of pointers each, 70 KB
  for all 19), and for Chinese, Japanese and Korean a system font loaded at start (below). The atlas
  stays the same size.

## Where the translations come from

`tools/ui/gen_strings.py` reads upstream Moonlight XR's
(github.com/Gilleece/moonlight-android-xr, GPLv3) `app/src/main/res/values/strings.xml` and each
`values-<lang>/strings.xml` and writes `ui/ui_strings_i18n.inc`, committed, so the build needs no
upstream checkout. Its `MAP` lists every key of `ui_strings.h` and where its translations come from:

* `SAME`: upstream has the key with the same meaning (106 keys).
* an upstream key: the same text under another name (5: Cancel, Close, Send, Back, Ray).
* `DRIFT`: upstream has the key, but this port's English now says something else (5: the
  "left View + grip" shortcut and toast, where upstream names the menu button; the About tab's
  report line and the report sheet's explanation and Save button, where upstream sends and this
  port saves). Upstream's translation would be wrong, so these stay English.
* `NATIVE`: written for this port, English until a person translates them (how many is in the
  generated part below).

So 111 keys are shared with upstream, as the PLAN counted; 106 of them are taken, plus the 5 aliases.

Android's quoting and escapes are resolved (`\'`, `\"`, `\n`, `\uXXXX`, whitespace, markup),
numbered formats (`%1$s`) become plain C ones, and a translation whose values differ from the
English format (reordered, another type, a `%` where the English has none) stays English, so a
translated format can never take other arguments than the code passes.

Upstream's 19 complete languages are in. Left out: the languages upstream translated only for its
Android screens (13 of the headset's strings or fewer: Bulgarian, Greek, Hungarian, Indonesian,
European Portuguese, Romanian, Vietnamese, Esperanto, Latvian; the panels would be English with a
word here and there), Hebrew (right to left: the text drawing has no bidi), Tamil (needs shaping),
Persian and Kurdish (nothing translated).

At run time `ui_str` returns the chosen language's text, or the English where it has none
(`ui_str_lang`, `ui_str_translated`; language 0 is English).

### Regenerating

```sh
git clone --depth 1 https://github.com/Gilleece/moonlight-android-xr /tmp/upstream
tools/ui/gen_strings.py --res /tmp/upstream/app/src/main/res --upstream-rev "$(git -C /tmp/upstream rev-parse --short=12 HEAD)"
```

It rewrites `ui/ui_strings_i18n.inc` and the generated part of this file. `tools/ui/gen_strings.py
--verify` (run by the `ui_i18n_gen` test) needs no upstream: it checks that every key of
`ui_strings.h` has a `MAP` line and that the committed table was made from this `MAP`.

### Adding a string to `ui_strings.h`

Add a `MAP` line for it in `tools/ui/gen_strings.py`, in the same place: `NATIVE` for a string
written for this port (no regeneration needed), `SAME` or an upstream key when upstream has it
(regenerate). Without the line `ui_i18n_gen` fails and names the key. Changing the English of a
`SAME` key so that it means something else makes it `DRIFT`.

### Translating a native string

A person who speaks the language writes `tools/ui/native/values-<dir>/strings.xml` in upstream's
format (`<string name="native_forget">...</string>`), with keys from `MAP`'s `NATIVE` and `DRIFT`
lines only, and regenerates. No translation here is made by a machine: an English fallback is
better than a guess, and the lists below are the work left.
